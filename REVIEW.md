# REVIEW.md

## Defects Found in Starter `app/main.py`

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` | Did not test database connectivity; returned static `{"status": "ok"}` even when MongoDB was unreachable. | Stop MongoDB service and call `GET /health`; it still returned 200 OK instead of 503. | Added `client.admin.command("ping")` inside a `try/except` block, returning 200 on success and 503 Service Unavailable on connection error. |
| 2 | `create_employee` | No schema validation on `shift_start`/`shift_end` (accepted invalid strings or equal start/end times), no email regex validation, and check-then-insert race condition on duplicate `emp_code`. | Send `shift_start: "25:99"` or create duplicate `emp_code` concurrently; causes 500 or duplicate inserts. | Implemented Pydantic model with regex validators for `HH:MM` (validating `00:00`–`23:59`, `shift_start != shift_end`), email format, and unique index catching `DuplicateKeyError` to return 409 Conflict. |
| 3 | `create_employee` | Accepted client-provided `created_at` timestamp rather than enforcing a server-generated UTC timestamp. | Client passes arbitrary past/future timestamp in request body and it gets saved. | Excluded `created_at` from input schema and generated it server-side using `datetime.now(timezone.utc)`, returning epoch ms. |
| 4 | `list_employees` | Allowed `page=0`, and calculated offset as `skip = page * page_size`, skipping the first page of results. | Requesting `page=1, page_size=10` skipped the first 10 employees. Requesting `page=0` returned 200 instead of 422. | Added validation `page >= 1` (returning 422 if `< 1`), and corrected offset formula to `skip = (page - 1) * page_size`. |
| 5 | `list_employees` | Total count ignored the `department` query parameter filter. | Calling `GET /employees?department=Sales` returned items filtered by Sales, but `total` reflected all employees across all departments. | Applied the department filter dictionary `{department: dept}` to `count_documents()`. |
| 6 | `list_employees` | Missing deterministic sort order by `emp_code` ASC. | Results returned in arbitrary natural MongoDB insertion order. | Added `.sort("emp_code", ASCENDING)` to the database query. |
| 7 | `punch_in` | Unknown employee code caused an unhandled 500 error or created orphan attendance records. | Send punch-in for non-existent `EMP9999`; returned 500 Internal Server Error. | Added check against `db.employees.find_one({"emp_code": ...})` returning HTTP 404 if not found. |
| 8 | `punch_in` | Allowed status `ABSENT` and `LEAVE` on punch-in requests. | Sending `POST /attendance/punch-in` with `status: "ABSENT"` succeeded. | Constrained punch-in status to `Literal["PRESENT", "WFH", "ON_DUTY"]`, returning 422 for absent/leave. |
| 9 | `punch_in` | Accepted floats, strings, booleans, and seconds-scale timestamps for `punched_at`. | Sending `punched_at: 1783312500` (seconds) or `punched_at: 1783312500000.5` (float) was accepted or caused type crashes. | Enforced Pydantic `StrictInt` and checked range `100_000_000_000 <= punched_at <= 2_500_000_000_000`, returning 422 otherwise. |
| 10 | `punch_in` | Check-then-insert race condition: `find_one()` followed by `insert_one()` allowed concurrent requests to insert duplicate records for the same employee and date. | Send 20 parallel punch-in requests for the same employee and date; multiple records were created. | Created a unique compound index on `(emp_code, date)` and caught `DuplicateKeyError`, returning 409 Conflict for all but the winning request. |
| 11 | `compute_late_minutes` | Late grace period calculation used integer division before comparison (`int(diff_seconds / 60) > 10`), evading penalties at 10 minutes and 1 second. | Punch-in at `09:40:01` on a `09:30` shift gave `601 // 60 = 10`, returning 0 late minutes instead of 10. | Evaluated raw difference in seconds strictly: `if diff_seconds > 600: return int(diff_seconds // 60)`. |
| 12 | `compute_work_hours` & `round_half_up` | Used Python's built-in `round()`, which applies round-to-even (banker's rounding). | `round(2.555, 2)` rounded down to `2.55` instead of `2.56` per R4/R8 specifications. | Implemented custom `round_half_up()` using Python's `decimal.Decimal` with `ROUND_HALF_UP`. |
| 13 | `punch_out` | Missing atomic conditional update; check-then-update allowed concurrent requests to overwrite punch-outs. | Send 10 parallel punch-outs for the same employee/date; multiple requests returned 200 OK. | Used atomic `find_one_and_update({"emp_code": ..., "date": ..., "punch_out": None}, ...)` returning 200 for the winner and 409 for the rest. |
| 14 | `punch_out` | Overtime calculation omitted the 30-minute minimum threshold (R3); overnight shifts failed to locate open records across midnight. | Punching out 15 minutes after shift end credited 15 minutes of overtime. Punching out at 06:00 for a 22:00 shift looked up the current date instead of the shift start date. | Enforced threshold `diff_minutes >= 30` for overtime; matched open punch-out records by finding existing open record where `punch_in <= punched_at`. |
| 15 | `regularize_attendance` | Allowed regularizing to `ABSENT`/`LEAVE` with non-null punch timestamps; accepted empty change requests; lacked concurrency protection on `history`. | Sending PATCH with empty body returned 200; concurrent edits lost audit trail entries. | Enforced null timestamps when regularizing to ABSENT/LEAVE; verified at least one actual change is made (returning 422 if none); used atomic `$set` and `$push` with retry logic for safe audit trails. |
| 16 | `employee_monthly_analytics` | Working days calculation counted all weekdays in the month even for mid-month joiners; weekend logs inflated `present_days`. | Employee joined July 13 was evaluated against 23 working days instead of 15. Saturday shift counted as present weekday. | Computed working days starting from `max(month_start, joined_on)`; filtered present day credit strictly to Monday–Friday logs per R6/R7. |
| 17 | `department_summary` | Pipeline grouped directly on `attendance_logs`, causing employees with zero logs to disappear from headcount, and included future joiners (R9). | Employee with no attendance logs was omitted from headcount. Future joiners were counted in past months. | Started pipeline from `employees` filtering `joined_on <= month_end`, and joined logs using `$lookup`. Averages calculated over raw records per contract. |
| 18 | `late_leaderboard` | Truncating results using Python slicing `[:limit]` or array indexes dropped tied employees at the rank boundary. | Two employees tied at Rank 2 with `limit=2`; second employee was dropped, returning 2 rows instead of 3. | Utilized `$setWindowFields` with `$rank` for 1-2-2-4 competition ranking, followed by `$match: {"rank": {"$lte": limit}}` and secondary sort by `emp_code` ASC. |
| 19 | `department_trend` | Grouped only on existing logs, leaving gaps for weekends and days without records. | Requested 7-day range returned only 3 rows if only 3 days had attendance records. | Generated a complete calendar date series inside the pipeline using `$range` and `$dateAdd`, then left-joined attendance logs to guarantee exactly one row per calendar day. |
| 20 | Multiple endpoints | Exposed internal MongoDB `_id` and `"id"` fields in JSON responses. | API responses leaked BSON ObjectId strings to the client. | Implemented response transformers that explicitly strip `_id` and `"id"`, converting all BSON datetimes to epoch milliseconds. |

## Items Examined and Determined NOT to Be Defects

1. **`GET /attendance` without date filters**: The starter allowed querying attendance without `date_from` and `date_to`. We verified against `openapi.yaml` that `date_from` and `date_to` are optional query parameters, not mandatory. Handling empty date parameters by returning the full paginated list is compliant with the contract.
2. **PATCH allowing transition to ABSENT / LEAVE**: Some might assume regularizing is only for marking presence. However, HR administrators frequently need to correct accidental punches or retroactively mark approved leave. Allowing status transition to ABSENT/LEAVE while resetting punch times to null is valid business logic.
3. **Synchronous PyMongo Driver**: FastAPI works smoothly with synchronous PyMongo for low-to-medium thread concurrency when queries are properly supported by compound indexes and execute in sub-millisecond time. Rewriting to Motor/async was unnecessary and would add complexity without contract benefit.
